# GV1 Studio

Красивый локальный конвертер MP4 и разрешённых к скачиванию видео YouTube в формат **GV1** для ESP32-S3 медиаплеера. Интерфейс публикуется на GitHub Pages, а FFmpeg, yt-dlp и передача на локальный ESP32 выполняются маленьким helper-сервисом на компьютере.

**[Открыть GV1 Studio](https://iliasnovickov-cmd.github.io/gv1-studio/)** · **[Скачать v1.0.0](https://github.com/iliasnovickov-cmd/gv1-studio/releases/tag/v1.0.0)** · **[Исходный код](https://github.com/iliasnovickov-cmd/gv1-studio)**

> Видео не загружается на сторонний сервер: обработка и промежуточные файлы остаются на вашем ПК.

## Возможности

- MP4 drag-and-drop с прогрессом локальной передачи;
- автоматическое приведение любого большого разрешения к 320×180 без искажения пропорций;
- Lanczos-масштабирование, чёрные поля и адаптивное JPEG-сжатие до лимита прошивки 32 КиБ на кадр;
- 24 FPS и PCM 48 кГц stereo, синхронизированные по точной длине GV1;
- загрузка одного обычного видео YouTube через yt-dlp после явного подтверждения прав;
- асинхронный прогресс, отмена задачи и понятные ошибки;
- скачивание готового файла с CRC32/SHA-256;
- ручной или автоматический режим **«Сразу отправить на плеер»**;
- потоковая передача на ESP32 с Content-Length и CRC32 в запросе;
- тёмный адаптивный интерфейс для компьютера и телефона;
- локальная страница работает даже без GitHub Pages.

## Почему нужен локальный helper

Статический HTTPS-сайт GitHub Pages не может сам запустить native FFmpeg/yt-dlp и не должен напрямую обходить ограничения YouTube. Кроме того, современные браузеры ограничивают HTTPS → локальный HTTP и Private Network Access. Helper решает это безопасно: слушает только **127.0.0.1**, разрешает проверенные GitHub Pages origins, обрабатывает PNA preflight и самостоятельно отправляет результат на ESP32. Если Chrome/Edge не выдаёт GitHub Pages разрешение на локальную сеть, нажмите **«Открыть локально»** или запускайте **start_windows.bat** — он откроет тот же интерфейс на **http://127.0.0.1:8765/** без browser mixed-content ограничений.

## Установка на Windows

Требуются Windows 10/11 и подключение к интернету при первой установке.

1. Скачайте репозиторий и распакуйте его.
2. Дважды нажмите **start_windows.bat**.
3. При первом запуске создастся изолированное окружение и установятся зависимости. Если FFmpeg отсутствует, скрипт установит его через winget.
4. Откроется **http://127.0.0.1:8765/**.
5. Оставляйте окно helper открытым во время работы.

Отдельно запустить установку можно так:

~~~powershell
powershell -ExecutionPolicy Bypass -File ./install_windows.ps1
~~~

## Использование

### MP4

1. Откройте локальную страницу или опубликованный GitHub Pages сайт.
2. Перетащите MP4.
3. При желании задайте имя .gv1.
4. Укажите адрес плеера, например **http://192.168.1.54**.
5. Оставьте включённым **«Сразу отправить на плеер»** или скачайте результат вручную.
6. Нажмите **«Начать конвертацию»**.

### YouTube

1. Перейдите на вкладку YouTube.
2. Вставьте обычную ссылку youtube.com или youtu.be.
3. Подтвердите, что владеете видео или имеете разрешение на скачивание.
4. Запустите задачу.

Плейлисты, live-трансляции, cookies, учётные данные и DRM-обход намеренно не поддерживаются. Доступность YouTube зависит от сети и региона; helper не обходит блокировки провайдера.

## Отправка на ESP32

Плеер и компьютер должны находиться в одной сети. На экране ESP32 должна быть открыта медиатека: в существующей прошивке Wi-Fi и HTTP намеренно выключаются во время воспроизведения для стабильного видео. Если передача не удалась, вернитесь из видео в библиотеку, проверьте IP и нажмите **«Отправить»** повторно.

Helper принимает только literal private/link-local HTTP-адреса и не следует redirect. Прошивка повторно читает принятый файл, сравнивает CRC32, проверяет GV1 и лишь затем атомарно заменяет целевой файл.

## Точный GV1

- 32-байтовый little-endian header;
- индекс по 8 байт на каждый кадр;
- independent JPEG 320×180, CFR 24/1;
- каждый JPEG не более 32768 байт;
- PCM signed 16-bit LE, 48000 Hz, 2 channels;
- audio = frames × 8000 байт с pad/truncate;
- полный файл и offsets меньше 4 ГиБ;
- запись через временный файл, fsync и atomic replace;
- CRC32 и SHA-256 полного результата.

Подробный API и переменные окружения описаны в [helper/README.md](helper/README.md).

## Разработка и тесты

~~~powershell
py -3.11 -m venv .venv
uv pip install --python .venv/Scripts/python.exe -r helper/requirements-dev.txt
cd helper
../.venv/Scripts/python.exe -m pytest -q
../.venv/Scripts/python.exe run.py --port 8765
~~~

Статический frontend находится в **docs/** и не требует npm или сборки. GitHub Pages публикует эту папку напрямую из ветки main.

## Проверено

- 24 backend-теста;
- native FFmpeg integration: тестовый источник 1280×720 автоматически уменьшается до точных JPEG 320×180;
- MP4 → 48 кадров → валидный двухсекундный GV1;
- результат 540809 байт, CRC32 **1A1089E7**, SHA-256 **A85A9C888AC3DC58439CA6220234D1CD9A25268AF1D0E804561D1E49691538E4**;
- GitHub Pages HTTP 200, CORS/PNA preflight и локальный fallback;
- запуск интерфейса в Chrome и обнаружение helper 1.0.0;
- строгий ESP32 upload-emulator принял ровно 540809 байт с Content-Length, без chunked Transfer-Encoding, CRC32 1A1089E7 и валидным GV1;
- Windows installer под Windows PowerShell 5.

Реальный запрос к YouTube из среды разработки был заблокирован сетью (timeout/reset до youtube.com), поэтому yt-dlp покрыт модульными тестами, но доступность конкретного видео всегда зависит от сети пользователя.
